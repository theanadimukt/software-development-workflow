# /review routing

Goal: assess a change for correctness, maintainability, and release risk.

Start with `code-review-and-quality`. Add `security-and-hardening` for untrusted input, identity, authorization, sensitive data, payments, or exposed endpoints; `performance-optimization` for resource, rendering, latency, or query concerns; and `api-and-interface-design` for public or cross-team contracts. Use `documentation-and-adrs` only when the review identifies a lasting decision that needs recording.
