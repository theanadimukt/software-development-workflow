# /spec routing

Goal: define a clear, testable outcome before implementation.

Start with `spec-driven-development` for meaningful features. Add `grill-with-docs` for consequential ambiguity, `idea-refine` when the product idea is still vague, and `constraint-driven-development` when quality, platform, or framework constraints need defining. Add `api-and-interface-design` for APIs, webhooks, or cross-client contracts; `improve-codebase-architecture` for new boundaries or architectural change; `frontend-ui-engineering` only for material UI behavior; and `security-and-hardening` for sensitive data, permissions, payments, or trust boundaries.

Do not select every candidate. A dark-mode request may need only specification plus UI expertise; subscription billing may also warrant ambiguity, interface, and security expertise.
