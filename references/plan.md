# /plan routing

Goal: turn a clear objective into an ordered, verifiable implementation plan.

Start with `planning-and-task-breakdown`. Add `context-engineering` for unfamiliar repositories, `api-and-interface-design` for contracts between components or systems, `improve-codebase-architecture` for structural choices, and `source-driven-development` when a plan depends on current external documentation. Use `deprecation-and-migration` when a rollout retires or changes an existing contract.
